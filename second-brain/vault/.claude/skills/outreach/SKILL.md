# /outreach
One send-ready message in the right pattern: short, human, proof-led, with one concrete ask. Routing: mid tier (recurring ask 10).

## Read first
- The post, thread, job description or draft being answered, the attachment, and the recipient's `07-People` note if one exists, newest versions (M6); say which you use.
- `.claude/rules/career.md` for job outreach: it loads only when a resume file is touched, so read it here.
- __OS_DIR__/output-standards.md: Writing voice (cold outreach register, natural writing blocks, no sycophancy); Formatting bans; Resume rules for the locked fact base and the kill-list claims.
- __OS_DIR__/templates.md: T52 (outreach message pattern); T53 (warm-intro message); T54 (note sharing an own build); T38 (internal update to the partner); T39 (client cover note); T37 (account visit pack) for pre-read emails; T34 (talk track); T50 (resume architecture and fact base) for proof points and contact details.
- __OS_DIR__/identity.md: Roles and employers for titles and dates only. The fact base wins over identity.md and every other file on every number and contact field.
- __OS_DIR__/active-areas.md: Job transition, or the engagement the message serves (status, good output, rejected).

## Steps
1. Name the reader, the one outcome wanted and the pattern, then follow that template's order exactly: T52 cold note to a hiring manager or recruiter; T53 when someone referred __OWNER__; T54 sharing __OWNER__'s own build; T38 update to the partner; T39 cover note to a client; T37 pre-read email; T34 talk track for a session.
2. Cold notes (T52): open on the post's own language or one verified finding from the attached POV; two proof points from the fact base; the fit gap named in one line; one concrete ask with timing; the close T52 specifies, with contact details exactly as the fact base holds them.
3. Warm intros (T53): send in working hours, with the CV PDF named properly.
4. Own builds (T54): state the build's honest maturity, directional where it is directional, and where it applies.
5. Partner updates (T38): every review point with how it was handled; dependencies stated plainly.
6. Client cover notes (T39): say which numbers are illustrative and raise data as the critical path, constructively, with the request list attached. Pre-reads (T37) name the sender and the send-by date.
7. Another tool's draft: keep what is true and specific, cut the rest, rewrite to the pattern; never polish a claim the record cannot support.
8. Register: succinct, humane, confident without boasting, problem-aware rather than self-declaratory; proof through what __OWNER__ did, not adjectives; natural writing blocks in email, chat and posts. A post in __OWNER__'s own voice is short, punchy and personal, never an op-ed.
9. Attach a POV as PDF with speaker notes removed; never attach a firm-templated deck or engagement material; check firm policy on outside work before anything goes to an outside party.
10. Set one follow-up about ten days out.

## Rules enforced here
- M4: proof points only from the locked fact base; kill-list claims never return; titles and dates from identity.md, every number and contact field from the fact base.
- A note sharing __OWNER__'s own build credits data __OWNER__ collected, scraped or verified as __OWNER__'s own primary work, never as supplied, third-party or vendor data [B4].
- A finding quoted in a message cites its primary producer, traced to the original publisher, never an aggregator or intermediary that repackages it [B5].
- Private instructions, reviewer personas, thinking-direction notes and working notes never appear in a message, an attachment, its speaker notes, comments or document properties; strip them before sending [B6].
- Client-facing notes carry no extreme or absolute statements (the list in output-standards.md); neutral maturity wording names the stage reached so the client is not put on the defensive; verbatim quotes and legal guardrail wording are exempt [A13].
- No sycophancy toward the reader, their firm or their post.
- One message, one ask; no hedging, no throat-clearing, no closing summary.

## Delegate
- Verifying the finding, the post's wording or the recipient's role to runner, with source and date.
- The POV deck behind a cold note to /pov; resume or cover letter changes to /resume; whether to approach a role at all to the fit call in /interview.

## Output
- In chat: the message ready to paste, subject line first for email, then one line naming the attachment and the follow-up date.
- Once sent: log it in the recipient's `07-People` note (interaction log, last_contact, follow_up); client and partner notes also go to the engagement hub's actions table (T5, decision and action log); job outreach also goes in `05-Self/Career/<Company> <Role>.md`.
- M1 no em dashes. M3 an attached client deck is a final deck; what changed goes in the cover note, never in slide text. M4 fact-base numbers and contact details only; kill-list claims never return. M5 never invent a number, source, quote or case; unverifiable claims are cut, not caveated. M6 answer the latest thread and attach the latest file version, named.
