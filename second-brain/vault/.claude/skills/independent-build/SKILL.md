# /independent-build
The next version of an independent build (model, data product, civic analysis or its capability deck) at a bar a senior partner or investor would be proud of. Routing: top tier for design (recurring asks 7 and 19); data pulls and QA on runner.

## Read first
- Latest version of the build, its build log and every input __OWNER__ has shared for it (M6); state which version you are building on.
- __OS_DIR__/output-standards.md: Deck rules (Template discipline; Numbers and evidence; Design), Excel and data rules, Anti-hallucination, and the second verbatim-corrections list in full.
- __OS_DIR__/templates.md: T40 (market pillars), T41 (unit brief), T42 (story step grammar), T43 (number classes), T44 (capability deck storyline), T45 (use-case table by industry), T46 (outlet-density model method), T31 (micro-market cascade), T54 (note sharing an own build).
- __OS_DIR__/active-areas.md: the build's entry under Independent and civic (status, good output, rejected, open decisions).
- __OS_DIR__/identity.md: Built assets and How I think, for what is __OWNER__'s own work and the quality bar.
- __OS_DIR__/thinking-patterns.md: Questions I ask; What I push on; Closed debates (settled product-shape questions stay settled).

## Steps
1. List every input __OWNER__ has asked for, this round and earlier ones; the list is the completeness checklist.
2. On opening a big build, ask the one or two decisions that change the design, then proceed.
3. Benchmark first: set a real-world deliverable that defines the bar beside the build, and state what this version must match and beat and what it gives that existing vendors and tools do not. Judge __OWNER__'s version only after that.
4. Design on this tier: the questions per T40, the unit view per T41, each story step per T42, the cascade per T31. A variable earns its place by answering a question another view uses.
5. Data: real, validated sources only, each named by its primary producer and date; __OWNER__'s own collected data credited as such; every figure carries its T43 class, directional versus exact called out.
6. Build the views: method text per view, a distinct colour scheme per view, sources in subscript or hover, nothing private in the product. Civic builds keep a data-only register, let the data structure argue the conclusion and stay bilingual when the brief asks.
7. QA in the render: map alignment, colours, coverage counts by unit, every prior layer and language still present, every checklist item ticked.
8. Story and sharing: T44 for the capability deck and T45 for use cases; T46's public-description rules whenever the model is described outside; T54 when the build is shared, its maturity stated honestly.
9. After a correction, restructure completely; never patch a rejected structure.

## Rules enforced here
- Variables talk to each other: no dump of metrics; each view connects its variables into one reading a senior partner can act on without going through every element [B1].
- Sources sit in subscript, footnote or hover, never called out in headlines or body text where they break the flow [B2].
- Coverage at the level the model claims: no threshold or floor that leaves most units unscored, and partial coverage is never called a model at that level [B3].
- __OWNER__'s own data work is credited as __OWNER__'s, never described as supplied by someone else [B4].
- Each data set is credited to its primary producer, never to an aggregator that republishes it [B5].
- Private instructions, thinking-direction notes and reviewer personas never appear in the product [B6].
- Each view or layer gets a colour scheme clearly distinct from the others [B7].
- Reference visuals are recreated in __OWNER__'s own style, never pasted as snapshots that carry another firm's look [B8].
- Method text changes with the view, level or lens selected; one static block is a defect [B9].
- Map surfaces sit exactly on the geographic outline, checked in the rendered output, not in code [B10].
- Every requested input is captured; the step 1 checklist is reconciled item by item before anything is called done [B11].
- No fake, illustrative or placeholder data anywhere, and no AI slop.

## Delegate
- Data pulls, scraping, cleaning, joins, coverage counts and render QA to runner, in parallel where independent.
- The capability deck's mechanical build to /deck-build; the sharing note to drafter.
- An independent check against T3 and the rules above to critic before anything is shared.

## Output
- The build files in the build's working folder, plus a dated build-log entry: decisions, sources with producer and date, coverage counts, number-class mix, open gaps.
- In chat: what the version now does, the checklist with ticks, coverage counts and the gaps that remain.
- M1 no em dashes. M3 any deck from the build is a final deck. M5 no fake or illustrative data; "I do not have reliable data on this" where data is missing. M6 build on the latest version and say which.
