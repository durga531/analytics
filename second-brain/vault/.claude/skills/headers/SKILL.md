# /headers
One best set of headers, sub-points or key insights, ready to paste, that reads as one argument. Routing: mid tier (recurring ask 4).

## Read first
- The latest version of the deck, chart or text the headers sit on (M6); where __OWNER__ has edited the file, that edit is the base [C1]. Say which file and date you work from.
- `.claude/rules/work.md`: path-scoped rules load only when a work file is touched, so read it for chat-only header work.
- __OS_DIR__/output-standards.md: Writing voice (header and sub-point lengths, one-sentence synthesis); Formatting bans (banned and extreme words, headline limits); Deck rules, subsections Storyline and headers, and Language.
- __OS_DIR__/templates.md: T16 (partner-level insight block); T17 (four-horizon capability table); T13 (deck intake and cardinal rules) for headline families, title rules and banned words with replacements; T19 (argument-first headline chain) as the exemplar of titles that carry the case alone.
- __OS_DIR__/active-areas.md: the area the work serves (good output, rejected), including lever or framework names already sent back as too long.
- __OS_DIR__/thinking-patterns.md: Frameworks (where to play, how to win, where to exit); Challenge vs execution (partner-blessed wording is execution, not debate).

## Steps
1. Fix the unit: slide action titles, an insight block (T16), a capability table (T17), lever or framework names, or a one-sentence synthesis. Lengths follow the unit: headers 3 to 4 words (4 to 5 for levers), sub-points 6 to 8 words, one sub-point per header when partner level is asked; action titles follow the T13 title rules and the headline limits in output-standards.md (length, punctuation, no contrast constructions).
2. Read the source (chart, data, transcript or deck) and write the so-what each header must carry; a header that restates the chart is a label, not an insight.
3. Draft against one frame, MECE across the set: the three CEO decisions (where to play, where to win, what to exit) for a T16 block, five insights at most; the four horizon columns for T17, three to four points each.
4. For slide titles, pick the T13 headline family per slide (aspiration, gap diagnosis, solution direction, benchmark, case study, transformative idea).
5. Silent critique pass before showing: overlap, generic or AI-sounding wording, banned words, length breaches, a value figure in the lead, extreme words. Rewrite every failure, then read the whole set in sequence as one storyline.
6. Show one best set, never a menu of options unless asked; partner-blessed wording appears unchanged and marked as kept.

## Rules enforced here
- Key insights are clean, complete sentences stating a non-obvious implication, with at most one or two numbers each; no number strings, fragments or restatement of the chart [A3].
- Every line is formal, specific and defensible in client and practice vocabulary; never a slogan, colloquial line or sweeping claim, and each makes sense read alone [A4].
- No header, section lead or executive-summary line opens with or commits to a value figure or range; lead with what the solution addresses and what is being built [A5].
- No extreme or absolute words; neutral maturity wording that names the stage reached. A finalised header stays as it is unless __OWNER__ reopens it [A13].
- Sources never sit in a header or sub-point; they go in the source line, subscript or hover [B2].
- Headers read in sequence as one compelling, flowing storyline; after a critique, rework the whole set until it reads end to end, never patch one line [C1].
- Client headers carry no exact numbers: percentages, approximations or "most". Partner-blessed wording is final and used verbatim.
- Lever and framework names stay short; no term or code appears before the slide that defines it.

## Delegate
- A storyline that breaks under the headers is strategic: hand it to /storyline.
- Fact checks behind a header (validate or disprove, with source and date) to runner.
- Writing approved headers into the deck to /deck-build; wording-only passes across a whole deck to /lexicon.

## Output
- In chat, ready to paste: the set as a numbered list in deck order (header | sub-point, or title only), kept partner wording marked; then one line naming the frame used.
- No preamble, no rationale per line unless asked, no closing summary.
- M1 no em dashes. M3 final-deck wording: no version language or new tags. M5 never invent a number or source behind a header; a gap reads "to validate". M6 work from the latest file and name it.
